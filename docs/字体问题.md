# 字体大小 / 粗细不一致 —— 已解决

> **English summary**: after localisation some Simplified-only characters (厅、览、编、购…)
> looked thinner/smaller than their neighbours. The cause is that the game's built-in
> `NotoSansTC-Medium` / `NotoSansTC-Bold` fonts only contain **20,748** CJK codepoints and
> have no glyphs for many Simplified characters, so those characters fall back to a system
> font. The fix is to replace `m_FontData` of those two `Font` assets inside the
> `Preload/Android/prologdepengroup-…-mxprolog-*.bundle` with a full Simplified font
> (Noto Sans SC), save the bundle with `pack="original"` and restore its original CRC32.
> Since v1.1.0 this step is **part of the one-click Windows script** (`运行.bat` /
> `localize_phone.ps1` calls [`tools/patch_font.py`](../tools/patch_font.py) automatically
> and downloads the two fonts, ~17 MB, on first run). Skip it with `-SkipFont`, or run the
> tool by hand — see below.

---

## 状态

**已解决。** 通过替换游戏内置的中文字体资产，可以让简体字与繁体字使用同一款字体，
粗细、大小完全一致。本文记录现象、根因、最终做法，以及早期 8 次失败实验的历史结论
（那些实验排除了错误路径，仍值得保留）。

> 本仓库**不包含**任何游戏资源。字体文件（Noto Sans SC Regular / Bold，`.otf`）也只在
> **首次运行一键脚本时自动下载**（也可以手动放进脚本目录的 `fonts\`）；原版资源包直接
> 从设备上拉取。

## 现象

汉化后界面文本 100% 正确、功能完全正常，但同一行文字里：

- **简体独有的字**（厅、览、编、购、辉、办、务、动…）看起来**更细 / 更小**
- **繁简同形的字**（活、石、任、咖、啡、青）保持正常
- 一个词里混用两种字形观感，例如「咖啡厅」的「厅」明显偏细

## 根因

游戏 UI 的中文字体来自客户端内置的两个 Unity `Font` 资产：

| 资产名 | cmap 字符数 | 说明 |
|---|---|---|
| `NotoSansTC-Medium` | 20,748 | 繁体常用字子集，**缺大量简体字形** |
| `NotoSansTC-Bold` | 20,748 | 同上 |

这两个字体是**按繁体文本裁剪过的子集**，cmap 里没有「厅 / 览 / 编 / 购 / 辉 / 办」
这类简体字。Unity 渲染时缺字会走**系统字体 fallback**：

```
内置字体缺字 → 系统字体补一个字
   ↓
同一行里两种字体混排 → 字重 / 字面大小不一致
```

所以问题不在翻译文本，也不在 TMP 字体资产（TMP 只是引用这两个 `Font`），
而在 **`Font.m_FontData` 里的字体文件本身**。

## 真正生效的是哪个包（关键）

真正被 UI 加载的中文字体在：

```
<设备>/Android/data/com.nexon.bluearchive/files/PUB/Preload/Android/
    prologdepengroup-assets-_mx-uis-_mxcommon-_mxprolog-*_assets_all_*.bundle
```

这个包约 11 MB，里面是 `prolog` 场景依赖组；两个 `Font` 资产（`NotoSansTC-Medium` /
`NotoSansTC-Bold`）就在其中。**文件名带日期和 hash，游戏每次更新都可能变**，
所以不要记文件名，用脚本的 `--find` 现找。

## 为什么之前 8 种办法都无效（历史记录）

早期排查时试过下面 8 种手段，**渲染结果全部没有变化**：

| # | 手段 | 结果 | 为什么无效（后来才确认） |
|---|---|---|---|
| 1 | 改外部 bundle 中 TMP 字体资产的源字体引用 | ❌ | TMP 不是最终字形来源，且改的不是这个包 |
| 2 | 给 bundle 中 0 字节的空壳 `Font` 资产填字体数据 | ❌ | 空壳 Font 不在渲染路径上 |
| 3 | 移植其它区服（国服）的 TMP 字体资产 + 图集 + 源字体 | ❌ | 改的包不对，UI 根本不加载它 |
| 4 | 替换系统字体（中日韩 4 款全换） | ❌ | 游戏优先用内置字体，系统字体只补缺字 |
| 5 | 替换 APK 内置字体（4 款） | ❌ | 不在这个 bundle 里；且改 APK 需重签 |
| 6 | 把 TMP 图集设为运行时可写 + 提供源字体 | ❌ | 静态图集，运行时不会重建 |
| 7 | 替换 APK 内置**全部 12 款**字体（按 cmap 精确判断） | ❌ | 同上，目标包在下载目录而非 APK |
| 8 | 改写系统 `/system/etc/fonts.xml` fallback 链 | ❌ | 内置字体存在时 fallback 链不会被走到 |

共同错误：**改的包位置不对**。当时替换的是 `.ttf` bundle、`.asset` bundle、
APK 内 `assets/bin/Data/*`，而真正生效的是 `Preload/Android/` 下那个
`prologdepengroup-…-mxprolog-*.bundle`。在错误的位置上做再多的替换，
游戏加载的还是原来那份字体。

> 早期结论「安卓端不自带中文字体 / 无字体资产可改」是**错的**：内置字体确实存在，
> 只是藏在上面那个 prolog 包里。8 次实验的价值在于逐一排除了这些路径。

## 一键流程（推荐）

双击 `运行.bat`，或跑：

```powershell
.\localize_phone.ps1
```

脚本在推回文本之后自动完成字体处理：

1. 检查 `UnityPy` + `lz4`（缺了只提示 `pip install -r requirements.txt`，然后跳过字体，
   不影响文本汉化）；
2. 找字体：`fonts\NotoSansSC-Regular.otf` / `fonts\NotoSansSC-Bold.otf` → 脚本目录下的
   `NotoSansSC-*.otf` → 从 [Release 1.1.0](https://github.com/alisns1/blue-archive-gl-simplified/releases/tag/1.1.0)
   下载（两个合计约 17 MB）。断网或下载失败会打印手动下载指引并跳过；
3. `adb shell ls` 列出 `Preload/Android/` 下所有 `prologdepengroup*.bundle`，全部拉到
   `work\font\pull\`（小包也拉，`--find` 需要扫描），并把原包备份到 `work\font\orig\`；
4. 跑 `patch_font.py --find` 自动认出含字体的那个包并生成补丁，确认 CRC32 与原值一致；
5. 推回原路径，再用 `md5sum` 复核设备上的文件与本地产物一致；
6. 打印 `fonts unified (restart the game once if it still shows the old font)`。

开关：

```powershell
.\localize_phone.ps1 -SkipFont                            # 跳过字体阶段
.\localize_phone.ps1 -FontRegular <path> -FontBold <path>  # 手动指定思源黑体
```

字体阶段是**可选增强**：任何一步失败只打印 `[!!]` 并继续，文本汉化结果不受影响；
已经拉出的原包会留在 `work/font/orig/` 供回滚。字体依赖也不在脚本的自动 pip 安装里
（那套只负责 `sqlcipher3`），缺了就按提示手动装一次。

## 手动做法（进阶 / 排查）

> 一键流程失败、或者想自己核对每一步时，按下面的手动步骤执行。
> 手动做法需要**自备**原版资源包（可从设备拉）和思源黑体。

### 前置准备

- 原版 `prologdepengroup-…-mxprolog-*.bundle`（**先备份**，回滚要用）
- 思源黑体简体：`NotoSansSC-Regular.otf`、`NotoSansSC-Bold.otf`
- Python 3.10–3.13 + `UnityPy==1.25.2`：

  ```bash
  pip install -r requirements.txt     # 或只装字体依赖：pip install UnityPy==1.25.2 lz4
  ```

  （1.25.4 依赖 `tpk_ar`，没有预编译 wheel，装不上）

### 第一步：找到当前的 bundle

```bash
python tools/patch_font.py --find "<设备>/.../PUB/Preload/Android"
```

脚本会扫描目录下所有 `.bundle`，打印含 `NotoSansTC` 的文件（通常只有一个）。
`--find` 只读，不改任何东西。用 Git Bash / WSL 的话，也可以先粗筛一下：

```bash
grep -l --binary-files=text "NotoSansTC" <设备>/.../PUB/Preload/Android/*.bundle
```

（`grep` 默认把二进制文件当「binary file matches」处理，`-l` 只列文件名；Windows 自带
的 `findstr` 对二进制不可靠，建议直接用 `--find`。）

### 第二步：打补丁

```bash
python tools/patch_font.py \
  --bundle  prologdepengroup-assets-_mx-uis-_mxcommon-_mxprolog-XXXX_assets_all_YYYY.bundle \
  --regular NotoSansSC-Regular.otf \
  --bold    NotoSansSC-Bold.otf \
  --out     prologdepengroup-assets-_mx-uis-_mxcommon-_mxprolog-XXXX_assets_all_YYYY.patched.bundle
```

可加 `--dry-run`：完整走一遍加载、替换、保存、校验，但**不写文件**，只打印结果。
建议第一次先 dry-run，确认两个字体都找到了、CRC 能对上。

脚本内部做三件事（这三步缺一不可）：

1. **替换 `m_FontData`**：按资产名找到 `NotoSansTC-Medium` / `NotoSansTC-Bold`，
   只换字体字节，**资产名和 PathID 保持不变**（否则其它资产引用会断）。
2. **`env.save(pack="original")`**：保持原 bundle 的打包/压缩方式。
   用 `pack="lz4"` 重新压缩会把 header 的 flags 从 `0x243` 改成 `0xC2`，
   游戏直接加载失败（表现为闪退或界面空白）。
3. **改写 header 的 size 字段**：bundle 头 offset 30 处的 int64 记录文件总长度，
   替换字体后长度变了，必须同步写成新长度，否则读取越界。

### 第三步：CRC32 还原（脚本自动做）

游戏的 Addressables catalog 记录了每个 bundle 的 CRC32。文件被改过、CRC 对不上时，
客户端会**静默重新下载**官方包——表现就是「改了没效果」，重启后字体又变回原样。

脚本在文件末尾追加 **4 字节**，用 GF(2) 高斯消元解出这 4 个字节，使**整个文件**的
CRC32 等于原值（末尾 4 字节不参与 bundle 解析，因此不影响加载）。
脚本最后会打印原 CRC、新 CRC 和是否 match，并自带自检。

### 第四步：推回设备

```bash
adb push <patched.bundle> /sdcard/Android/data/com.nexon.bluearchive/files/PUB/Preload/Android/<原文件名>.bundle
```

**文件名必须和原文件完全一致**（catalog 按文件名+路径索引）。

## 关键坑

| 坑 | 说明 |
|---|---|
| **必须 `pack="original"`** | 用 lz4 重压会改 flags（`0x243` → `0xC2`），游戏加载不了 |
| **必须还原 CRC32** | 不还原 → 游戏静默重下官方包 → 看起来「没生效」 |
| **文件名会变** | bundle 名带日期/hash，版本更新后旧名字不存在 → 用 `--find`（或 `grep -l "NotoSansTC"`）重新找 |
| **资源热更会覆盖** | 游戏内「资源修复 / 重新下载」或热更会把这个包换回官方版 → 重跑脚本即可 |
| **必须改 header size** | 只换字体不改长度 → 读取越界/加载失败 |
| **不要改 PathID** | 换资产对象而不是新建对象，PathID 才能保持不变 |
| **推之前关游戏** | 文件被占用时 push 会失败或写坏 |

## 验证方法

1. push 前记录本地文件 md5；push 后再从设备 `adb shell md5sum` 一次，确认一致。
2. **重启游戏**（不是切后台，要杀掉进程重进）。
3. 再取一次设备上的 md5：
   - **没变** → CRC 校验通过，游戏没有重新下载；
   - **变回官方值** → CRC 没对上（或热更覆盖），重新检查脚本输出里的 `match`。
4. 进游戏看三处字形：**咖啡厅**（厅）、**编辑**（编）、**活动一览**（览）。
   简体字与周围字粗细、大小一致即成功。

## 回滚

一键流程跑过之后，原包会自动备份到 `work\font\orig\`（文件名与原文件名相同）。
把备份的原版 bundle push 回原路径、覆盖即可，不需要其它操作：

```bash
adb push <备份的原版.bundle> /sdcard/Android/data/com.nexon.bluearchive/files/PUB/Preload/Android/<原文件名>.bundle
```

以下数据来自修复前的分析，留着方便后来者核对，**不代表当前结论**：

APK 内 `assets/bin/Data/<GUID>`（Unity 序列化资产）中的字体：

| 字体 | cmap 字符数 | 缺简体独有字形 |
|---|---|---|
| `NotoSansTC-Medium` | 20,748 | ✗（厅 览 编 购 辉 办） |
| `NotoSansTC-Bold` | 20,748 | ✗（同上） |
| `MALGUN`（韩） | 27,133 | ✗ |
| `MainFont` / `MainFont_Bold` | 12,294 / 12,293 | 韩文标题字体，几无中文 |

TMP 资产 `U-OTF-ShinMGoUpr-DeBold SDF`：

```
m_AtlasPopulationMode = 1（动态）
m_SourceFontFile      = { m_FileID: 0, m_PathID: 0 }   ← 空
m_SourceFontFileGUID  = 'bac7aba6…'                    ← 本客户端不存在该文件
m_GlyphTable          = 13,235 个字形（烘焙自原繁体文本）
m_AtlasTextures[0].m_IsReadable = False                 ← 运行时不写
```

其它事实：

- `--find` 和 `grep` 都是在 bundle 的**原始字节**里搜 `NotoSansTC`（名称字符串在文件头附近有明文），
  字体数据本身仍是压缩的，不能直接搜到字体内部内容
- `UnityPy==1.25.4` 依赖 `tpk_ar`（仅 sdist，需 Rust 编译）→ 用 `1.25.2`
- 替换下载目录中的 bundle，客户端只校验 CRC32，不校验签名

## 注意

- 本方案**不需要 root**，也**不需要改 APK / 重签**；只替换下载目录里的一个资源包。
- 修改客户端文件严格来说违反游戏用户协议，风险请自行评估。
- 本仓库不提供游戏资源或成品 bundle；字体由一键脚本首次运行时下载（也可自备），
  原版包从设备拉取。
- 字体问题**不影响任何功能**：即使不打这个补丁，文本内容也是 100% 正确的。
